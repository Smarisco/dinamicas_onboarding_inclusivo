# DIN-REV-001 — Checklist de Materiais
## CRSG — Code Review Simulation Game

> **Duração:** 55 min | **Participantes:** 2–6 | **Modalidade:** Digital

---

## Pré-Dinâmica

### Materiais
- [ ] Código-fonte com defeitos intencionais preparado — impresso ou em arquivo digital
- [ ] Syntax highlighting ativo no código distribuído (não plain text)
- [ ] Checklists de revisão com 5 categorias: Bug | Code Smell | Segurança | Performance | Legibilidade
- [ ] Exemplo de comentário construtivo vs. destrutivo preparado para exibição
- [ ] Gabarito do facilitador com todos os defeitos e categorias — não distribuir antes do fim
- [ ] Projetor ou tela compartilhada configurada — fonte ≥ 14pt para leitura coletiva

### Participantes
- [ ] Número confirmado (2–6) e modalidade definida (individual ou duplas)
- [ ] Facilitador preparado para explicar os 5 tipos de defeito com exemplos
- [ ] Estrutura completa anunciada antes de iniciar: ler → identificar → categorizar → comentar → comparar
- [ ] Papel de registrador disponível como alternativa na revisão coletiva

---

## Durante a Execução

### Fases
- [ ] Exemplo de comentário construtivo vs. destrutivo exibido antes da prática (5 min)
- [ ] Revisão individual/dupla (20 min): checklist em uso; 1 comentário escrito por defeito encontrado
- [ ] Revisão coletiva (15 min): código projetado com fonte ≥ 14pt; percorrer linha a linha
- [ ] Prática de reformulação (5 min): 1 comentário destrutivo reformulado em construtivo
- [ ] Gabarito do facilitador revelado ao final para comparação objetiva

### Acessibilidade Sensorial (TEA)
- [ ] Código com syntax highlighting — nunca plain text
- [ ] Checklists com categorias explícitas distribuídos antes — sem categorização espontânea exigida
- [ ] Revisão individual concluída antes de exposição coletiva — sem surpresa pública
- [ ] Participante com ansiedade de feedback público pode atuar como registrador na revisão coletiva

---

## Pós-Dinâmica

### Debriefing
- [ ] Pergunta-chave lançada: *"Quais defeitos ninguém encontrou? O que isso nos diz sobre nossos pontos cegos?"*
- [ ] Lição central registrada: **Code review é uma skill — checklists e prática aumentam cobertura**
- [ ] Compromisso pessoal escrito por cada participante (1 categoria a verificar explicitamente)

### Registro
- [ ] Defeitos encontrados por participante/dupla anotados
- [ ] Categoria com menor cobertura coletiva identificada
- [ ] Defeitos não encontrados por ninguém listados
- [ ] Observações sensoriais (pressão de encontrar defeitos, feedback público) registradas
- [ ] Template de debriefing preenchido e arquivado
